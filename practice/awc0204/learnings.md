## アルゴリズム・考え方

### 1. 「値ごとの個数」で持つ（C）

- 「価格が B の商品をすべて C にする」のような、**同じ値をまとめて変える操作**は、商品を 1 個ずつ見ると間に合わない。
- 「値 → その値の個数」を持てば、1 回の操作が O(1) で済む。
- 総和は差分だけ更新する：`total += (C - B) * 個数`。
- 個数を移すときは、**B = C の場合に消えないか**を確認する（今回は B ≠ C が保証されていた）。

### 2. DP の定義を「ちょうど j」から「j 以下」に変える（D）

- 「高さがちょうど j」で定義すると、遷移で `min(dp[i-1][0..j])` が必要になり、そのままだと O(NM²) かかる。
- 「**j 以下**」で定義すると、累積 min が DP の式の中に入り、O(NM) になる。

  ```
  dp[i][j] = min(dp[i-1][j] + C[i][j],  dp[i][j-1])
  ```

- 「広義単調増加にする」「k 以下を選ぶ」のような条件の DP で、よく使う形。

### 3. DP をきれいに書くコツ（D）

- 使うのが 1 つ前の行だけなら、配列 1 本を上書きしていけば足りる（メモリ N×M → M）。
- **初期値をうまく選ぶと場合分けが消える**。
  - `dp = [0] * m`：「0 台なら料金 0」とすれば、1 台目も同じ式で計算できる。
  - `best = inf`：左端の「左側」が無いことを inf で表せば、j = 0 も同じ式で計算できる。

### 4. 偶奇付き Union-Find（E）

- 「2 つの値が **同じか違うか**」という条件が並んでいたら、偶奇付き Union-Find（または BFS で 2 色に塗る）。
- `par[v]` = 「v の値 xor 親の値」を持ち、`find` のときに根までの xor を足し込む。
- 2 つの成分をつなぐときは `par[根a] = par[a] ^ par[b] ^ t`。
- 同じ成分の中で関係が食い違ったら矛盾（答えが存在しない）。
- 行と列のように 2 種類の頂点があるときは、`0..H-1` を行、`H..H+W-1` を列にして番号をまとめる。

### 5. 連結成分ごとの 2 択を DP でまとめる（E）

- 連結成分の中は 1 頂点の値を決めると全部決まるので、成分ごとの選び方は「そのまま」か「全部反転」の 2 通りしかない。
- 「押す個数の合計が偶数」のような**全体にかかる制約**は、その偶奇を DP の状態に入れる：`dp[p]` = 偶奇 p のときの最小費用。
- 条件が付いていない行や列も、1 頂点だけの成分として同じように扱える。

### 6. 「押す順番は関係ない」と気づく（E）

- 反転操作は何回反転したかの偶奇だけで結果が決まる。そのため、各スイッチを「押す / 押さない」の 0/1 で表せる。
- マス (r, c) の最終的な色 = `x_r xor y_c`。

## Python の書き方

- **出力が多いときはまとめて出す**：`print("\n".join(map(str, out)))`。10^5 行を超えると、毎回 `print` するより目に見えて速い。
- **入力が多いときは一括で読む**：`sys.stdin.buffer.read().split()`（E のように M が 2×10^5 行ある場合など）。
- `str.find(x)` は、見つからないとき `-1` を返す。
- `Counter(a)` で個数を、`sum(a)` で総和を作れる。
- `for b, c in bc:` のように取り出すと、`bc[i][0]` と書くより読みやすい。
- 値の範囲が小さい（〜10^6）なら、dict より配列 `[0] * (MAX + 1)` の方が速い。
- Union-Find の `find` は再帰でなくループで書く（再帰が深くなると落ちる・遅い）。
